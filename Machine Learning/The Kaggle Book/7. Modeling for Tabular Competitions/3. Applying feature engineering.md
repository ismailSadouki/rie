# Easily derived features
Deriving features with transformations is the simplest approach, but often the most effective. For instance, computing feature ratios (dividing one feature by another) can prove quite effective because many algorithms cannot mimic divisions (for example, gradient boosting) or can have a hard time trying to (for example, deep neural networks). Here are the most common transformations to try out:
- Time feature processing: Splitting a date into its elements (year, month, day); transforming it into week of the year and weekday; computing differences between dates; computing differences with key events (for instance, holidays).
For dates, another common transformation is extracting time elements from a date or a time. Cyclic continuous transformations (based on sine and cosine transformations) are also useful for representing the continuity of time and creating periodic features:
```
cycle = 7
df['weekday_sin'] = np.sin(2 * np.pi * df['col1'].dt.dayofweek /cycle)
df['weekday_cos'] = np.cos(2 * np.pi * df['col1'].dt.dayofweek /cycle)
```

## 🧠 The Problem: Cyclic Features

Some date/time features are **cyclic (circular)** — meaning they _wrap around_ after reaching a maximum value.

For example:

| Feature       | Range  | Wraps Around?                      |
| ------------- | ------ | ---------------------------------- |
| Hour of day   | 0 → 23 | Yes (after 23 comes 0)             |
| Day of week   | 0 → 6  | Yes (after Sunday comes Monday)    |
| Month of year | 1 → 12 | Yes (after December comes January) |

### ⚠️ The Problem with Treating Them as Numeric

If you use these features _as raw numbers_, the model sees **false distances**.

Example:

| Hour | Meaning | Distance? |
| ---- | ------- | --------- |
| 23   | 11 PM   | —         |
| 0    | 12 AM   | —         |
Numerically, the distance between 23 and 0 is **23**,  
but in time, they are **just one hour apart**!

So the model can’t understand that the feature _loops_ around — it thinks midnight is far from 11 PM.

## 🔄 The Solution: Cyclic (Sine–Cosine) Transformation

To handle this, we **map cyclic features onto a circle** using sine and cosine transformations.

For a feature xxx that cycles through values [0,M)[0, M)[0,M):
![](https://i.imgur.com/6ft8hg2.png)


This way:

- The feature “wraps around” smoothly.
    
- 23:00 and 00:00 become **close** in the transformed space.


### 🧩 Why It Works

- Sine and cosine represent **positions on a unit circle**.
    
- The model can “see” the cyclic structure, because:
    
    - Adjacent times are close in 2D space.
        
    - The start and end of the cycle are connected smoothly.
### 🧠 When to Use It

Use sine/cosine encoding for **any periodic feature**, such as:

- Hour of day (period = 24)
    
- Day of week (period = 7)
    
- Month of year (period = 12)
    
- Day of year (period = 365)

# Meta-features based on rows and columns
In order to perform competitively, you need trickier feature engineering. A good place to start is looking at features based on each row, considered separately:
- Compute the mean, median, sum, standard deviation, minimum, or maximum of the numeric values (or of a subset of them)
- Count the missing values
- Compute the frequencies of common values found in the rows (for instance, considering the binary features and counting the positive values)
- Assign each row to a cluster derived from a cluster analysis such as k-means
These meta-features (called thus because they are features that are representative of a set of single features) help to distinguish the different kinds of samples found in your data by pointing out specific groups of samples to your algorithm.

Meta-features can also be built based on columns. Aggregation and  operations on single features instead have the objective of providing further information about the value of numeric and categorical features; is this characteristic common or rare? This is information that the model cannot grasp because it cannot count categorical instances in a feature.

As meta-features, you can use any kind of column statistic (such as mode, mean, median, sum, standard deviation, min, max, and also skewness and kurtosis for numerical features). For column-wise meta-features, you can proceed in a few different ways:
- <mark>Frequency encoding: Simply count the frequency of the values in a categorical feature and then create a new feature where you replace those values with their frequency. You can also apply frequency encoding to numeric features when there are frequently recurring values.</mark>
- Frequencies and column statistics computed with respect to a relevant group: In this case, you can create new features from the values of both numeric and categorical features because you are considering distinct groups in the data. A group could be a cluster you compute by cluster analysis, or a group you can define using a feature (for instance, age may produce age groups, locality may provide areas, and so on). The meta-features describing each group are then applied to each sample based on its group. For instance, using a Pandas groupby function, you can create your meta-features, which are then merged with the original data based on the grouping variable. The trickiest part of this feature engineering technique is finding meaningful groups in data to compute the features on.

---
## 🧠 What It Means

> “Frequencies and column statistics computed with respect to a relevant group”

means that instead of computing global statistics (over the _whole dataset_),  
you compute **summary statistics within meaningful groups** of data.

In other words:

> You find patterns _inside subgroups_ (clusters, age ranges, cities, etc.)  
> — not across the entire dataset.

This helps the model understand **local patterns** that are hidden in the overall data.

# Using feature importance to evaluate your work
- Classical approaches used in statistics resort to forward addition or backward elimination by testing each feature entering or leaving the set of predictors. Such an approach can be quite time-consuming, though, because it relies on some measure of internal importance of variables or on their effect on the performance of the model with respect to a specific metric, which you have to recalculate for every feature at every step of the process.
- For regression models, using lasso selection can provide a hint about all the important yet correlated features (the procedure may, in fact, retain even highly correlated features), by using the stability selection procedure. In stability selection, you test multiple times (using a bagging procedure) what features should be retained – considering only the features whose coefficients are not zero at each test – and then you apply a voting system to keep the ones that are most frequently assigned non-zero coefficients.
- For tree-based models, such as random forests or gradient boosting, a decrease in impurity or a gain in the target metric based on splits are common ways to rank features. A threshold can cut away the least important ones.
- Always for tree-based models, but easily generalizable to other models, test-based randomization of features (or simple comparisons with random features) helps to distinguish features that do help the model to predict correctly from features that are just noise or redundant.

An example of how randomizing features helps in selecting important features is proposed in this example by Chris Deotte in the Ventilator Pressure Prediction competition: https://www.kaggle.com/cdeotte/lstm-feature-importance. This Notebook tests the role of features in an LSTM-based neural network. First, the model is built and the baseline performance is recorded. Then, one by one, features are shuffled and the model is required to predict again. If the resulting prediction worsens, it suggests that you shuffled an important feature that shouldn’t be touched. Instead, if the prediction performance stays the same or even improves, the shuffled feature is not influential or even detrimental to the model.

**Permutation Feature Importance (PFI)** is a technique to **measure how much each feature contributes to a model’s predictions**.

### 🔹 How it works

1. Train your model as usual.
    
2. Measure its performance on a validation/test set (e.g., accuracy, RMSE, F1).
    
3. For a given feature:
    
    - Randomly **shuffle (permute)** its values across the dataset.
        
    - This breaks the relationship between that feature and the target.
        
    - Re-evaluate the model performance.
        
4. The **drop in performance** = the importance of that feature.
    

If shuffling a feature causes a **big performance drop**, the model heavily relies on it.  
If performance barely changes, the feature is **less important**.


### 🔹 Advantages

- Works with **any model** (tree-based, linear, neural nets).
    
- Easy to implement and interpret.
    
- Captures the **true predictive power** of a feature in context of others.
    

### 🔹 Limitations

- Computationally expensive (requires multiple evaluations).
    
- Correlated features can confuse it: if two features carry the same info, shuffling one won’t drop performance much.
    
- Sensitive to test set choice.
    

### 🔹 Example

Suppose you train a model to predict **house prices** with features:  
`[square_footage, location, number_of_rooms, year_built]`.

- Shuffle `square_footage` → model accuracy drops a lot → **very important**.
    
- Shuffle `year_built` → accuracy barely changes → **less important**.
    



⚡ In short:  
**Permutation Feature Importance = measure of how much model performance decreases when a feature’s information is destroyed.**

In another approach based on shuffled features, Boruta (https://github.com/scikit-learn-contrib/boruta_py) uses random features to test the validity of the model in an iterative fash-ion.

---
## What is Boruta?

- Boruta is a feature selection algorithm originally developed in R (as the “Boruta” package).
    
- It is _all-relevant_ — meaning it aims to find **all** features that carry useful information (not just a minimal subset that gives good predictive performance). [GitHub](https://github.com/scikit-learn-contrib/boruta_py)
    
- It does this by comparing the importance of real features to “shadow” features (randomized copies), and progressively rejecting or confirming features as relevant or not. [GitHub](https://github.com/scikit-learn-contrib/boruta_py)
    

In contrast, many feature selection methods aim to find a _minimal_ or _optimal_ subset for a given model (i.e. only the most critical features), possibly discarding features that are truly informative but redundant given other features.


## How you’d use boruta_py in practice

Here’s a sketch:

1. **Choose a base estimator**  
    You pass in a model (e.g. `RandomForestClassifier`) that can provide `feature_importances_`.
    
2. **Initialize BorutaPy**  
    Set parameters like `n_estimators`, `perc`, `alpha`, `max_iter`, `two_step`, etc.
    
3. **Fit it on your data**  
    Call `feat_selector.fit(X, y)` where `X` is your feature matrix and `y` is the target vector. [GitHub](https://github.com/scikit-learn-contrib/boruta_py)
    
4. **Inspect results**
    
    - `support_` gives a boolean mask of features confirmed as relevant.
        
    - `support_weak_` gives features that are tentative (not confirmed or rejected).
        
    - `ranking_` gives a ranking (1 = confirmed, 2 = tentative, etc.).
        
5. **Transform your data**  
    Use `transform(X)` (or `fit_transform`) to select only the confirmed relevant features, producing a reduced feature matrix to feed into subsequent models.



## When & why to use it

You’d use **boruta_py** (or the Boruta approach in general) when:

- You care about understanding **all** predictive or relevant features in your data (for interpretability, scientific insight), rather than just getting the smallest model with good performance.
    
- You have (or can use) a tree-based ensemble method that supports `feature_importances_`.
    
- You want a more robust way than simple univariate filtering, by comparing to randomized “shadow” features.
    
- You are concerned about overfitting / false discovery in feature selection and want to rigorously test whether features are truly informative vs noise.
    

However, keep in mind:

- It can be computationally expensive, especially with many features and large datasets (because of repeated fitting of the estimator, shadow features, multiple iterations).
    
- In very high-dimensional settings, or when features are heavily correlated, the algorithm might struggle or mark many features as tentative.
    
- It may not always pick a minimal subset; you may still want to do further pruning or model-based selection if you want a lean model.


---



An alternative version of the Boruta selection procedure, BorutaShap (https://github.com/Ekeany/Boruta-Shap), leverages SHAP values in order to combine feature selection and for explainability reasons. The resulting selection is usually more reliable than simple rounds of removal or randomization of features, because features are tested multiple times against random features until they can statistically prove their importance. Boruta or BorutaShap may take up to 100 iterations and it can only be performed using tree-based machine learning algorithms.

<mark>If you are selecting features for a linear model, Boruta may actually overshoot.</mark>
This is because it will consider the features important both for their main effects and their interactions together with other features (but in a linear model, you care only about the main effects and a selected subset of interactions). <mark>You can still effectively use Boruta when selecting for a linear model by using a gradient boosting whose max depth is set to one tree, so you are considering only the main effects of the features and not their interactions.</mark>


You can have a look at how simple and quick it is to set up a BorutaShap feature selection by following this tutorial Notebook presented during the 30 Days of ML competition: https://www.kaggle.com/lucamassaron/tutorial-feature-selection-with-boruta-shap.
