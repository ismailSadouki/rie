There are several methods of encoding categorical predictors to numeric columns
using the outcome data as a guide (so that they are supervised methods). These
techniques are well suited to cases where the predictor has many possible values or when new levels appear after model training.
The first method is a simple translation that is sometimes called effect or likelihood encoding. In essence, the effect of
the factor level on the outcome is measured and this effect is used as the numeric
encoding. For example, for the Ames housing data, we might calculate the mean or median sale price of a house for each neighborhood from the training data and use this statistic to represent the factor level in the model.
> [!note] 🎯 Why use this?
> - Efficient for **high-cardinality categorical variables** (e.g., 1000+ cities).
> - More **compact** than one-hot encoding.
> - Helps models like linear regression or trees learn **real signal** more easily.
> - Helps generalize to **new levels** (if done properly with smoothing or fallback strategies).

For classification problems, a simple logistic regression model can be used to measure the effect between the categorical outcome and the categorical predictor. If the outcome event occurs with rate p, the odds of that event are defined as p/(1 − p). As an example, with the OkC data, the rate of STEM profiles in Mountain View California is 0.53 so that the odds would be 1.125. Logistic regression models the log-odds of the outcome as a function of the predictors. If a single categorical predictor is included in the model, then the log-odds can be calculated for each predictor value and can be used as the encoding. As previously mentioned, there are different methods for estimating the effects. A
single generalized linear model (e.g., linear or logistic regression) can be used. While very fast, it has drawbacks. For example, what happens when a factor level has a single value? Theoretically, the log-odds should be infinite in the appropriate direction but, numerically, it is usually capped at a large (and inaccurate) value.

One way around this issue is to use some type of shrinkage method. For example, the overall log-odds can be determined and, if the quality of the data within a factor level is poor, then this level’s effect estimate can be biased towards an overall estimate that disregards the levels of the predictor. “Poor quality” could be due to a small sample size or, for numeric outcomes, a large variance within the data for that level. Shrinkage methods can also move extreme estimates towards the middle of the distribution. For example, a well-replicated factor level might have an extreme mean or log-odds (as will be seen for Mountain View data below).
> [!note] 📌 Why It Matters
> - Prevents **overfitting** from rare categories
> - Makes encodings **more robust**
> - Helps **generalize** better to new data (especially unseen levels)
> - Still allows you to use **categorical variables with many levels**, like city, profession, or zip code

A common method for shrinking parameter estimates is <mark>Bayesian analysis</mark>
in this case, expert judgement can be used prior to seeing the data to specify
a prior distribution for the estimates (e.g., the means or log-odds). The prior would be a theoretical distribution that represents the overall distribution of effects. Almost any distribution can be used. If there is not a strong belief as to what this distribution should be, then it may be enough to focus on the shape of the distribution. If a bell-shaped distribution is reasonable, then a very diffuse or wide prior can be used so that it is not overly opinionated. Bayesian methods take the observed data and blend it with the prior distribution to come up with a posterior distribution that is a combination of the two. For categorical predictor values with poor data, the posterior estimate is shrunken closer to the center of the prior distribution. This can also occur when their raw estimates are relatively extreme.
> [!note] 🧠 What's the Core Idea?
> Bayesian analysis combines two sources of information:
> 1. **Prior**: What we _believe_ about a parameter (e.g., log-odds of being in STEM for a city) **before seeing the data**.
> 2. **Data (Likelihood)**: What the **observed data** tells us about that parameter.
> The result is the **posterior**, which is a **compromise** between the prior belief and the observed evidence.
> ## 💡 Why Use Bayesian Shrinkage?
> When some levels of a categorical variable (e.g., cities, job titles) appear **rarely**, their **raw effect estimates** are unreliable and can be **too extreme**. Bayesian shrinkage **pulls those estimates closer to the overall pattern**, especially when the data is weak.
> ## 🔧 How It Works
> - Let’s say we are estimating the **log-odds** of being in STEM for each city.
> - For each city, we:
> - - Assume a **prior distribution** for the log-odds (e.g., a **normal distribution centered at 0**).
> - - Use the observed data for that city to calculate the **likelihood**.
> - - Apply Bayes’ Rule to get the **posterior estimate**.
>##### **This posterior**:
> - Will be **closer to the raw estimate** if the city has a lot of data (strong evidence).
> - Will be **closer to the prior (mean log-odds)** if the city has little data or high variability.
> - |City|Observed STEM Rate|Prior Log-Odds (from global rate)|Posterior Log-Odds|
|---|---|---|---|
|Mountain View (many obs)|0.53|~0.0|~0.12 (close to data)|
|TinyTown (1 obs)|1.0|~0.0|~0.05 (close to prior)|
> ## 📐 What’s a “Diffuse Prior”?
> A **diffuse prior** means it has **wide uncertainty** (e.g., a normal distribution with a large variance like N(0,100)\mathcal{N}(0, 100)N(0,100)).
> - It’s used when we **don’t want to be too opinionated** about the prior.
> - It lets the **data have more influence** when it’s strong.
> - But still offers some **shrinkage** when data is weak.
> ## 🛠️ When to Use Bayesian shrinkage?
> - You have **categorical variables with many levels**.
> - Some levels are **rare or unreliable**.
> - You want a **principled way to regularize** the effects and avoid overfitting.




For the OkC data, a normal prior distribution was used for the log-odds that has a
large standard deviation (σ = 10). Table 5.5 shows the results. For most locations,
the raw and shrunken estimates were very similar. For Belvedere/Tiburon, there was a relatively small sample size (and a relatively small STEM rate) and the estimate was shrunken towards the center of the prior. Note that there is a row for `“<new location>”`. When a new location is given to the Bayesian model, the procedure used here estimates its effect as the most likely value using the mean of the posterior distribution (a value of -1.79 for these data). Empirical Bayes methods can also be used, in the form of linear (and generalized
linear) mixed models (West and Galecki, 2014). These are non-Bayesian estimation methods that also incorporate shrinkage in their estimation procedures. While they tend to be faster than the types of Bayesian models used here, they offer less flexibility than a fully Bayesian approach.
