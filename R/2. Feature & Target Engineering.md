For instance, ordinary linear
regression models assume that the prediction errors (and hence the response)
are normally distributed. This is usually ﬁne, except when the prediction
target has heavy tails (i.e., outliers) or is skewed in one direction or the other.
A simple linear model, say
Sale_Price = 𝛽0 + 𝛽1 Year_Built + 𝜖, often assumes the error term 𝜖 (and
hence Sale_Price) is normally distributed; fortunately, a simple log (or similar)
transformation of the response can often help alleviate this concern as Figure
3.1 illustrates.
![](https://i.imgur.com/H7BIRx6.png)
There are two main approaches to help correct for positively skewed target
variables:
Option 1: normalize with a log transformation. This will transform most right
skewed distributions to be approximately normal. One way to do this is to
simply log transform the training and test set in a manual, single step manner
similar to:
```
transformed_response <- log(ames_train$Sale_Price)
```
That _changes_ the dataset directly.  
But — when you later get **new data** (like your test set or future unseen data), you’ll have to **repeat exactly the same preprocessing steps**.

If you forget the exact steps, or apply them slightly differently, you’ll get _inconsistent transformations_ → wrong predictions.

## 🧠 2️⃣ The idea: _Blueprint_

So instead of immediately transforming the data, tools like the **`recipes`** package (or `caret::preProcess`) let you **record the recipe** — a _blueprint_ describing _what to do_, but not doing it yet.

Think of it like a “cooking recipe”:

- You _write down_ “take log of Sale_Price, scale numeric columns, encode factors”
    
- But you don’t actually _cook_ until you apply it.
    

That blueprint can then be reused later — on your test data, on new data, etc. — and it will automatically apply _exactly the same transformations_ in the same way.


```
ames_recipe <- recipe(Sale_Price ~ ., data = ames_train) %>%
  step_log(all_outcomes())


```
If the nonpositive response values are small (say between
-0.99 and 0) then you can apply a small oﬀset such as in log1p() which adds
1 to the value prior to applying a log transformation (you can do the same
within step_log() by using the offset argument). If your data consists of
values ≤ −1, use the Yeo-Johnson transformation mentioned next.
