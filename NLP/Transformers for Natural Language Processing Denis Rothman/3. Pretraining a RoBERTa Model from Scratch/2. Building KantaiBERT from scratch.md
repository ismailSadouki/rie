# Step 3: Training a tokenizer
In this section, the program does not use a pretrained tokenizer. For example, a
pretrained GPT-2 tokenizer could be used. However, the training process in this
chapter includes training a tokenizer from scratch.

Hugging Face's ByteLevelBPETokenizer() will be trained using kant.txt. A byte-
level tokenizer will break a string or word down into a sub-string or sub-word.
There are two main advantages among many others:

•The tokenizer can break words into minimal components. Then it will merge
these small components into statistically interesting ones. For example,
"smaller" and smallest" can become "small," "er," and "est." The tokenizer
can go further, and we could obtain "sm" and "all," for example. In any case,
the words are broken down into sub-word tokens and smaller units of sub-
word parts such as "sm" and "all" instead of simply "small."
•The chunks of strings classified as an unknown unk_token, using WorkPiece
level encoding, will practically disappear.

In this model, we will be training the tokenizer with the following parameters:
•files=paths is the path to the dataset.
•vocab_size=52_000 is the size of our tokenizer's model length.
•min_frequency=2 is the minimum frequency threshold. # This is the **minimum number of times** a subword must appear in your dataset to be included in the vocabulary.
•special_tokens=[] is a list of special tokens.
```

In this case, the list of special tokens is:
•<s>: a start token
•<pad>: a padding token
•</s>: an end token
•<unk>: an unknown token
•<mask>: the mask token for language modeling
```
The tokenizer will be trained to generate merged sub-string tokens and analyze their frequency.

# Step 11: Defining a data collator
We need to run a data collator before initializing the trainer. A data collator will take samples from the dataset and collate them into batches. The results are dictionary like objects.
We are preparing a batched sample process for Masked Language Modeling (MLM) by setting mlm=True.

We also set the number of masked tokens to train mlm_probability=0.15. This will
determine the percentage of tokens masked during the pretraining process.
We now initialize data_collator with our tokenizer, MLM activated, and the
proportion of masked tokens set to 0.15:
```python
#@title Step 11: Defining a Data Collator
```

Great question 🚀 Let’s break this down clearly:

---

## 🔹 **BERT (Bidirectional Encoder Representations from Transformers)**

- **Introduced by Google (2018)**.
    
- Pretrained with:
    
    - **Masked Language Modeling (MLM)** → mask 15% of words and predict them.
        
    - **Next Sentence Prediction (NSP)** → predicts if one sentence follows another.
        
- **Architecture**:
    
    - Base: 12 layers, 12 attention heads, hidden size 768.
        
    - Large: 24 layers, 16 heads, hidden size 1024.
        
- **Strengths**: Great for sentence-pair tasks (e.g., question answering, entailment) because of NSP.
    

---

## 🔹 **RoBERTa (Robustly Optimized BERT Approach)**

- **Introduced by Facebook (2019)** as an improvement to BERT.
    
- **Key differences vs. BERT**:
    
    1. **No NSP** → Removed next-sentence prediction (they found it doesn’t help much).
        
    2. **More training data** → Trained on **160GB** vs. BERT’s **16GB**.
        
    3. **Longer training & bigger batches** → Trained much longer with more compute.
        
    4. **Dynamic masking** → Instead of masking the same tokens every epoch (like BERT), RoBERTa re-masks dynamically → more robust learning.
        
- **Architecture**: Same as BERT (encoder stack), but trained with these optimizations.
    
- **Strengths**: Usually **outperforms BERT** across most benchmarks, especially single-sentence classification and text similarity.
    

---

## 🔹 **When to use which?**

- ✅ **Use BERT** if:
    
    - You care about **sentence-pair relationships** (NSP might help in very specialized domains).
        
    - You want the "original" widely studied baseline.
        
- ✅ **Use RoBERTa** if:
    
    - You want **better performance on most NLP downstream tasks** (classification, QA, NER, etc.).
        
    - You don’t need NSP.
        
    - You want a more **robust and modern choice**.
        

---

👉 In practice:  
Today, people **mostly use RoBERTa (or DistilRoBERTa for smaller models)**, unless they specifically need **NSP-based tasks** or want to compare to the **original BERT baseline**.
