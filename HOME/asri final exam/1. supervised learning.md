#### Is Missingness Predictive? Target Rate Analysis
we analyzed the relationship between missingness intensity and the target variable by grouping observations into quantile-based bins of total missing values. For each group, we computed the target rate along with standard deviation and 95% confidence intervals. This allows us to assess whether missingness intensity carries statistically meaningful predictive information.
![](https://i.imgur.com/TmhQaYG.png)
The results show that the target rate varies across missingness levels, with higher missingness groups generally having a higher target rate (~0.80 vs ~0.74). However, the relationship is not strictly monotonic, indicating a more complex pattern. Overall, this suggests that missingness is not completely random (not MCAR) and contains predictive information about the target, likely reflecting structured mechanisms such as MAR or partially MNAR.

**Lift in Target Rate by Missingness Level**
![](https://i.imgur.com/UlFd8Rd.png)

The lift analysis shows that missingness intensity has a non-linear relationship with the target variable. While some intermediate missingness levels show near-neutral or slightly negative lift, both low and very high missingness groups exhibit deviations from the global baseline. In particular, the highest missingness group shows the strongest positive lift, indicating elevated risk. This confirms that missingness carries structured predictive information, although its effect is not monotonic.



> [!warning] **Critical**: **Never Drop the 90+ Missing Block**
> dropping high-missing rows would not necessarily improve modeling, because they still represent a large portion of the dataset and contain **structured information rather than pure noise**. However, the evidence here does **not strongly support the idea that they are a completely separate data feed**; instead, it suggests a **partially informative missingness mechanism (likely MAR with localized MNAR behavior)** rather than a fully distinct system.





###### **Missingness Pattern as a Standalone Predictor**

A logistic regression model was trained on **only the binary missingness matrix** (no actual feature values — just which columns are absent per row), evaluated with 5-fold stratified cross-validation:

![](https://i.imgur.com/jtUW0lb.png)
**AUC of 0.60 from zero feature values** confirms systematic MNAR behaviour. A random model gives 0.50; reaching 0.60 purely from absence patterns means the pattern of which values are missing carries substantial information about claim outcomes. **The model can and should exploit this structure explicitly.**




##### **Missingness Correlation Heatmap (top 20 highest-missing columns)**

##### **Hierarchical Clustering of Missing Patterns**

**Hierarchical clustering** of the columns based on how similar their missing-value patterns are
![](https://i.imgur.com/jBgtYvF.png)
**Branch A (upper):** Low-missing and fully complete columns. Contains `policy_type`, `coverage_type`, `claim_type`, `geographic_region`, `previous_claims_value`, `claim_detail_code`, `claim_source`, `policy_premium_annual`, `incurred_loss_estimate`, `claim_processing_days`, `policy_renewal_months`, `prior_denial_indicator`, `location_code`, `cross_sell_index`, all 12 fully complete columns, and `policy_status`. `policy_status` joins this branch rather than Branch B despite its high missingness. confirming its unique missingness pattern (seen in the correlation heatmap as the −0.1 correlation with other Tier 1 columns).

**Branch B (lower):** The structural missing block. This branch itself sub-divides into two sub-branches visible in the dendrogram: a tighter cluster (higher within-group similarity, near-zero linkage distance) containing Cluster 5 and parts of Cluster 4, and a broader cluster containing the rest of Cluster 4 and Cluster 3. The sub-structure within Branch B is what the cluster-based feature engineering exploits.


#### **cluster-based  engineered features**

We first identified variables containing significant missing values and transformed their missingness into binary indicators (1 = missing, 0 = observed). Using these binary missingness patterns, Hierarchical Agglomerative Clustering with Jaccard distance and average linkage was applied to group variables exhibiting similar missing-data behavior. For each resulting cluster, new features were engineered to summarize the missingness structure, including the proportion of missing values, the number of missing variables, and indicators showing whether all variables within a cluster were missing for a given observation. Finally, a baseline Logistic Regression model using only the original numerical variables was compared with an enhanced model incorporating the cluster-based missingness features. Model performance was evaluated using the ROC-AUC metric to assess whether structured missingness information improves predictive capability.

![](https://i.imgur.com/5NrFfBA.png)
the missingness-cluster features improved AUC from about **0.7038 to 0.7089**, which is a gain of roughly **+0.0051 AUC**. This again confirms that missingness in the dataset is not random and that groups of features tend to become missing together in ways related to the target.

***Permutation Importance: Top 20 Features:***

However, their predictive contribution is secondary compared to core financial and claim-related variables.

# CDF Analysis and comparison

For each numerical feature, we compared the distribution of the full population vs. the positive class (target=1) using CDF. The scaled difference between CDFs (KS-style) quantifies separation.
Features with large KS peaks = high discriminative power = useful for classification. 
Features where the CDFs overlap = no signal = candidates for removal.
**Top Features:**
![](https://i.imgur.com/MzkINIQ.png)

**prior_denial_indicator**
`prior_denial_indicator` is **The single strongest numerical predictor in this dataset.** 
we might create `has_prior_denial = (prior_denial_indicator > 0)` binary feature, plus keeping the raw value for tree models.
![](https://i.imgur.com/O0NzHld.png)

**claim_processing_days**
`claim_processing_days` 2nd strongest feature.
we might consider creating `is_fast_claim = (claim_processing_days < 1)` binary flag.

**zero-inflated binary signal** dressed as a continuous variable. 

`has_customer_value = (customer_value_score > 0)` is likely more predictive than the raw value. 
![](https://i.imgur.com/5wnPDaI.png)

**coverage_limit**
For `coverage_limit` The threshold at approximately **12–12.5** is the optimal split point (where the green curve peaks)

- High `coverage_limit` (> 12) → associated with class 1

# 14. Modelling Philosophy

This dataset has five defining properties that together dictate every modelling decision:
##### Property 1  Weak individual features, strong collective signal

The strongest individual numerical feature (`prior_denial_indicator`) has AUC = 0.687. The strongest categorical feature (`claim_detail_code`) has MI = 0.115. These are moderate numbers. No feature alone can drive a good classifier. The model must learn from multiple features simultaneously and discover their interactions.

**What that means:** Deep trees with many leaves, trained to many iterations, are essential. Shallow trees (max_depth < 5) will underfit. Linear models will underfit severely.

##### Property 2: Non-monotone signal in key features

`policy_renewal_months` has KS = 0.080 but AUC = 0.501, perfect proof that the discriminating signal is a spike at a single value (7), not a directional ranking. `previous_claims_value` has an oscillating CDF difference (U-shaped relationship). `recovery_probability` is effectively binary (1 vs 2) despite being continuous.

**What that means:** Any model that relies on monotone relationships (logistic regression, linear SVM, naive Bayes) will completely miss these signals. Only tree-based models or models with explicit non-linear feature engineering can exploit them.

##### Property 3  Extreme cardinality in the most informative categorical

`claim_detail_code` has 18,210 unique values and MI = 0.115. This is the single most informative feature in the entire dataset. Standard encoding approaches (OHE: memory crash, label encoding: wrong ordinality assumption) fail here. The model and the encoding strategy must be co-designed.

**What that means:** CatBoost handles this natively. LightGBM requires target encoding with CV. Linear models cannot handle this feature at all without complex preprocessing.

##### Property 4  Fabricated column names, true latent structure

The r > 0.97 correlation pairs confirm that multiple named columns are near-identical underlying signals. This creates two problems: importance instability (the model's importance scores randomly split between duplicates) and potential overfitting through spurious feature multiplication.

**What that means:** Deduplication of the correlation clusters is a mandatory, not just a preprocessing nicety. `api_response_quality` must be dropped (r = 0.998 with `witnesses_count`).

##### Property 5 Moderate class imbalance (3.17:1)

76.1% / 23.9% is not extreme (not 100:1) but it is significant. An uncorrected model will develop a strong prior toward class 1, systematically under-predicting class 0. All tree models have a `class_weight` or `scale_pos_weight` parameter that must be set.

**What that means:** All models must correct for imbalance. The correction method differs by model family .

# 15. Modeling

### LightGBM
LightGBM was selected for this task because  Its efficiently processes the large tabular data of approximately 90,000 rows and 131 features through histogram binning . Additionally, LightGBM effectively addresses the imbalanced classification nature of the task through per-sample weighting, and its high execution speed enables extensive hyperparameter searching across numerous trials.

Training used **Stratified K-Fold cross-validation** (3 folds) (Although 3 is not recommended for this dataset) and For each fold, the model tracks:
- **pAUC (FPR ≤ 0.1)**  the primary optimization target.
- **AUC** overall discriminative power.
- **PR-AUC class-0** precision-recall performance on the minority class.

**Class Imbalance Handling**
Because `scale_pos_weight` in LightGBM targets label=1 (the majority class here, making it the wrong direction), **per-sample weighting** was used instead:
- `n_neg` = 19,110 (class 0, minority)
- `n_pos` = 60,914 (class 1, majority)
- `natural_spw` = n_pos / n_neg = **3.17**
Two imbalance strategies were explored via Optuna:
- `"none"` equal weights for all samples.
- `"mild_weight"`  minority class samples (label=0) are upweighted by a factor `minority_weight ∈ [1.0, 3.17]`, while majority class samples remain at weight 1.0.
This approach gives the optimizer flexibility to tune the degree of class correction.

Other methods like SMOTE were also tested and they give similar results but it takes to much time. 

**Custom Evaluation: pAUC**
custom LightGBM evaluation function `pauc_eval_lgb` was registered, computing:
```
score = roc_auc_score(y_true, y_pred, max_fpr=0.1)
return "pAUC_01", score, True  # higher is better
```
This metric directly drives:

- **Early stopping** (100 rounds patience) via `LightGBMPruningCallback`.
- **Optuna's objective** function (returned as the trial score).
- All **fold-level reporting** (fold AUC, fold pAUC, fold PR-AUC).

This ensures complete consistency: the metric used for stopping, tuning, and evaluation is always pAUC on the validation set.

# More on Hyperparameter Tuning


**1. Population-Based Training (PBT)**
Population-Based Training combines random search with evolutionary refinement. A population of N configurations is trained in parallel; the best-performing trials continue, and weaker ones are replaced by mutations of the top performers. This explores the space more broadly than sequential Bayesian approaches.
![](https://i.imgur.com/iobVPgR.png)

![](https://i.imgur.com/bgzlcWB.png)
**2. Multi-objective Optimization (MOO)**
The most sophisticated approach used **CMA-ES (Covariance Matrix Adaptation Evolution Strategy)** combined with **multi-objective optimization** via Optuna's `NSGAIISampler` (Non-dominated Sorting Genetic Algorithm II).

Instead of purely maximizing pAUC (which can overfit), the optimizer simultaneously:
- **Maximizes** OOF pAUC (Objective 1: return `-oof_pauc` to minimize)
- **Minimizes** the train/validation pAUC gap (Objective 2: `mean_gap`) to penalize overfitting
This produces a **Pareto front** of non-dominated solutions representing the best trade-offs between performance and generalization.

**NSGA-II configuration:**

- Sampler: `NSGAIISampler` with `BLXAlphaCrossover`
- Population size: Pareto-front candidates maintained per generation
- Crossover and mutation probabilities: standard NSGA-II values

Three strategies were defined to select the final model from the Pareto front:

- **Strategy A**  Best pAUC (ignore gap): use when maximum performance is the priority.
- **Strategy B** Best gap (most regularized): use when generalization is critical.
- **Strategy C**  70% pAUC + 30% gap weighted score (balanced trade-off)  **selected as defaut**

CatBoost  specialises in high-cardinality categorical features. For this dataset, it is arguably the best single model because `claim_detail_code`  can be given to CatBoost raw, no manual target encoding required.

When computing the target statistic for a category value in a given training row, it only uses rows that appeared before that row in a random permutation. never including the row's own label.  **and this make it handles `claim_detail_code` better than LightGBM**

###  Recommendations

**1. Recalibrate predicted probabilities** Apply Platt scaling or isotonic regression on held-out validation set probabilities. The +0.1491 under-confidence bias directly causes the FN surplus of 7,463 test cases. Recalibration alone without any model changes would shift many FN cases above the threshold.

**2. Re-optimise the decision threshold** After recalibration, sweep the threshold using a business-cost-weighted criterion. The PR curve indicates 0.247 as the F1-optimal point, but the business may prefer a different FN/FP tradeoff. The current threshold of 0.52 is misaligned with the model's probability scale.

**5. Deduplicate correlated features ** The EDA identified and the sanity check confirmed 3,416 feature pairs with r > 0.97. Specifically: drop `api_response_quality` (r=0.998 with `witnesses_count`), drop one of `claim_complexity_score`/`liability_percentage` (r=0.993), review `medical_necessity_score`/`claim_validity_score` pair (r=0.982). This will stabilise SHAP importance and may modestly improve generalisation.

**6. Investigate feature distribution shift** Three features showed unexpected test-set behaviour vs. EDA: `risk_category` (low MI in training, rank 9 in test-error SHAP), `payment_method` (flat in training, rank 13 in test SHAP), `medical_necessity_score` (non-significant in training, p=0.030 in test). Run a KS test or PSI (Population Stability Index) between training and test distributions for these features to detect shift.

**7. Target FP-dominant clusters 2 and 3 with post-processing** Error cluster 2 (n=285, 75.8% FP) is compact enough to be targeted. Identify the feature profile of this cluster and apply a correction rule.

**9. Investigate high-confidence errors** The worst FPs (predicted probability ~0.97, true class 0) and worst FNs (predicted probability ~0.015, true class 1) cannot be fixed by threshold changes or recalibration. Manual inspection of these test cases  especially their `claim_detail_code` and `claim_channel` values  is needed to identify whether they represent data quality issues, label errors, or systematic model blind spots.
