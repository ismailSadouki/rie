This milestone is much less about writing code and much more about **freezing the experiment** and producing a reproducible training run. If your smoke run passed, you shouldn't be changing the training loop anymore.

Here's what I'd do.

---

## 1. Freeze a full-run config

Create something like:

`configs/train_first_full.yaml`

Do **not** reuse the smoke config.

Increase the model to your actual target (10–30M parameters) and choose the largest batch size that comfortably fits on the T4.

For example:

```yaml
seed: 42

batch_size: 8
gradient_accumulation_steps: 4

max_iters: 100000

eval_interval: 250
eval_iters: 50

learning_rate: 3e-4
min_lr: 3e-5
warmup_iters: 1000
lr_decay_iters: 100000

weight_decay: 0.1
betas: [0.9, 0.95]

grad_clip: 1.0

device: cuda
dtype: auto

model:
  vocab_size: 16000
  block_size: 1024

  n_layers: ...
  d_model: ...
  n_heads: ...
  n_kv_heads: ...
```

After you launch the run:

**Don't modify this file.**

If you want another experiment,

create

```
train_second_full.yaml
```

instead.

# 3. Save generations

Every few thousand steps generate from a fixed prompt.

For example

```
The history of artificial intelligence
```

Always use

```
seed = 42
temperature = 1.0
top_k = 50
```

Then save

```
runs/
    20260807_174200/
        samples/
            step_0.txt
            step_10000.txt
            step_20000.txt
            ...
```

These are **sanity checks**, not benchmarks.

# 6. Resume test

Very important.

Kill training.

Resume from

```
latest.pt
```

Verify

```
step continues

lr continues

optimizer continues

loss continues
```

No reset.

---

# 7. Record throughput

Instead of the first few noisy values,

average over thousands of steps.

Something like

```
Average throughput:
101,823 tokens/sec
```

is much more useful.

---

# 8. Record limitations

Don't wait until the README.

Write things like

```
Model is intentionally tiny.

No FlashAttention.

No FSDP.

Single GPU.

Tokenizer vocabulary limited to 16k.

Evaluation performed on 50 batches.
```

---

# 9. Don't chase generations

The milestone explicitly says

> convergence behavior, not impressive generations.

So the important artifacts are

- loss curve
    
- checkpoints
    
- throughput
    
- logs
    

not whether it writes coherent English.

---

## Validation checklist

From what I've seen, after completing the full run you should be able to honestly check:

- ✅ The run has a unique ID, frozen config, commit hash, and seed.
    
- ✅ Loss curve is saved.
    
- ✅ Best checkpoint loads in a fresh process.
    
- ✅ Throughput is averaged over many optimizer steps.
    
- ✅ Observations and limitations are written before polishing results.
    

After this milestone, the project moves away from "does training work?" toward measuring **systems performance** (MFU, efficiency, utilization, etc.), which is the next stage.
