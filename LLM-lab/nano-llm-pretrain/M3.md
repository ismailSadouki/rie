These are two of the tests you'll write before implementing the full model.

---

## 1. A tiny forward pass returns `[B, S, V]` logits

Suppose your config is

```python
batch_size = 2
seq_len = 16
vocab_size = 16384
```

Your input is

```python
input_ids.shape
```

```
[2, 16]
```

meaning

- B = 2 sequences
    
- S = 16 tokens each
    

The model predicts the probability of **every vocabulary token** for **every position**.

So the output must be

```
[B, S, V]
```

or

```
[2, 16, 16384]
```

because

- 2 batches
    
- 16 positions
    
- for each position, scores for all 16,384 vocabulary tokens
    

Graphically,

```
input_ids

[B,S]

↓

Embedding

[B,S,C]

↓

Transformer

[B,S,C]

↓

LM Head

[B,S,V]
```

where

- C = embedding dimension (e.g. 512)
    
- V = vocabulary size (16384)
    

The test will simply check

```python
assert logits.shape == (2, 16, 16384)
```

before you care whether the values are correct.

## 2. Loss is scalar when targets are provided

Suppose

```python
input_ids
```

has shape

```
[2,16]
```

and

```python
targets
```

also has shape

```
[2,16]
```

The model predicts

```
[2,16,16384]
```

Then computes cross entropy.

Internally, PyTorch computes one loss per token,

```
2 × 16 = 32 losses
```

then averages them.

So instead of returning

```
[2,16]
```

or

```
[32]
```

it returns a **single number**.

Example

```
tensor(4.82)
```

Its shape is

```
[]
```

called a **0-dimensional tensor**, or scalar.

So your test becomes

```python
logits, loss = model(input_ids, targets)

assert logits.shape == (2, 16, 16384)
assert loss.ndim == 0
```

or equivalently

```python
assert loss.shape == ()
```

---

## Why test this first?

Even before implementing attention, you know your model API is correct:

```python
logits, loss = model(input_ids)
```

returns

```
logits
[B,S,V]

loss
None
```

and

```python
logits, loss = model(input_ids, targets)
```

returns

```
logits
[B,S,V]

loss
scalar
```

If these shapes are correct, the rest of your training pipeline (`train.py`, evaluation, generation) can rely on a stable interface while you gradually fill in the model internals.
